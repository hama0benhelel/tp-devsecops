TP1 DEVSECOPS

Objectif du TP
L’objectif de ce TP est de mettre en pratique les concepts DevSecOps à travers la création, le
déploiement et l’automatisation d’une application Java avec Git, Docker et GitHub Actions. À la fin
de ce TP, les étudiants seront capables de :
• Utiliser Git pour versionner un projet et le pousser sur GitHub.
• Créer et tester une application Java avec Maven.
• Construire, tester et publier une image Docker.
• Configurer un pipeline CI/CD avec GitHub Actions.
• Ajouter une sécurité de base avec Gitleaks pour détecter les secrets dans le code.
Prérequis
Avant de commencer, assurez-vous d’avoir :
• Un compte GitHub.
• Un compte Docker Hub.
• Docker Desktop installé et démarré.
• Java et Maven installés sur votre machine.
• Git installé.
I. Partie1 : GIT
1. Créer un dépôt GitHub
Crée ton dépôt GitHub
• Cliquez sur "New Repository" (Nouveau dépôt).
• Donnez un nom à votre projet : tp-devsecops.
• Ne cochez pas la case "Initialize with README" (Initialiser avec un fichier
README).
• Cliquez sur "Create repository" (Créer le dépôt).

2. Initialiser Git
Créez un dépôt Git local pour votre projet.
• Assurez-vous que vous êtes bien dans le répertoire de votre projet.
• git init
=> Cette commande crée un dépôt Git dans votre projet (un dossier caché nommé
.git).
• Votre projet est maintenant suivi par Git.

3. Ajouter les fichiers
git add .

 Le point (.) indique que tous les fichiers du projet doivent être ajoutés.
 Cette étape prépare les fichiers pour le premier commit.
4. Premier commit
git commit -m "Initial commit"

TP1 DevSecOps Amara Balkis

 Un commit correspond à une capture instantanée (snapshot) de l’état actuel de votre
projet.
 Le message "Initial commit" décrit ce premier enregistrement.
5. Renommer la branche principale
git branch
git branch -M main

 -M : permet de renommer la branche actuelle, et force le changement si une autre
branche du même nom existe déjà.
6. Link Local Repository to GitHub
git remote add origin https://github.com/xxxxxxxx/tpdevsecops.git

 origin : nom standard utilisé pour désigner le dépôt distant.
7. Envoyer le projet sur GitHub (push)
git push -u origin main

 - u : définit main comme la branche par défaut pour les futurs push et pull.
Vous pouvez ensuite vérifier votre dépôt GitHub pour confirmer que les fichiers ont bien été
transférés.

III. Partie3 : Docker
1. Créer l’image Docker:
• Vérifiez votre nom d’utilisateur Docker (il sera utilisé pour nommer l’image).
• Ouvrez Docker Desktop afin de démarrer le service Docker.
Ensuite, dans votre terminal, exécutez les commandes nécessaires pour construire
l’image Docker de votre application.:

TP1 DevSecOps Amara Balkis

docker build -t username/democyber:latest .

Tester l’image en local:
docker run -p 8080:8080 tonusername/democyber:latest

Remarque :
L’option -p 8080:8080 permet de mapper le port 8080 du conteneur vers le port
8080 de votre machine locale.
Une fois le conteneur lancé, ouvrez votre navigateur et accédez à l’adresse suivante ::
http://localhost:8080

2. Publier l’image sur Docker Hub :
• Connectez-vous à Docker Hub depuis le terminal :
docker login
Entrez votre nom d’utilisateur et votre mot de passe Docker Hub lorsque cela est
demandé.

TP1 DevSecOps Amara Balkis

• Poussez (publiez) votre image sur Docker Hub :
docker push tonusername/democyber:latest

• Tester l’image depuis Docker Hub:
Téléchargez et exécutez l’image directement depuis Docker Hub pour vérifier qu’elle
fonctionne correctement :
docker run --pull always -p 8080:8080 tonusername/democyber:latest
Remarque:
Cette commande force Docker à télécharger la dernière version de l’image publiée
sur le Hub, même si une version locale existe déjà.

IV. Pipeline CI/CD de base
1. Ajouter le jeton (token) dans GitHub Actions
Il s’agit d’un mot de passe spécial qui permet à GitHub Actions de se connecter à
Docker Hub sans utiliser votre mot de passe réel.
Accédez à votre dépôt sur GitHub :
Settings → Secrets and variables → Actions → New repository secret

TP1 DevSecOps Amara Balkis

Ajoutez les deux secrets suivants :
• DOCKERHUB_USERNAME → votre nom d’utilisateur Docker Hub
• DOCKERHUB_TOKEN → votre jeton d’accès personnel (personal access token)
de Docker Hub

Étapes pour le créer:
1. Connectez-vous à Docker Hub.

2. Allez dans Personal Access Tokens (Jetons d’accès personnel).

TP1 DevSecOps Amara Balkis

3. Cliquez sur New Access Token (Nouveau jeton d’accès).

4. Donnez un nom à votre jeton (ex. : github-actions).
5. Cliquez sur Generate
6. Copiez immédiatement le jeton généré (vous ne pourrez plus le voir par la suite)
